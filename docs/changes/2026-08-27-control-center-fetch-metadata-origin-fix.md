# Control Center Fetch Metadata origin fix

Date: 2026-08-27

## Objective

Allow legitimate authenticated owner POST actions from the production iPhone/Safari Control Center without weakening the existing CSRF and Bob Core authorization boundaries.

## Production evidence

After PR #29 deployed, the owner still received the exact response:

```json
{"error":"Invalid request origin."}
```

That response is generated by the Web same-origin guard before the request reaches Bob Core. The pending Codex decision proposal remained open and unchanged.

The Bob Core decision approval SQL had already been exercised against the real pending proposal inside a rollback-only transaction. That test successfully created the decision, completed the review task, and created the approval event before rollback. Therefore the Bob Core/Neon storage path is healthy and the remaining failure is browser-to-Web request validation.

## Root cause

PR #29 improved the guard by comparing the browser `Origin` hostname with incoming `Host` and `X-Forwarded-Host` values. The production response proves Vercel's request-host metadata can still differ from the browser-visible production hostname on this path.

Relying only on proxy host preservation is therefore too brittle for the owner POST boundary.

## Fix

`Web/lib/request-origin.ts` now uses Fetch Metadata when the browser provides it:

- `Sec-Fetch-Site: cross-site` is rejected immediately;
- `Sec-Fetch-Site: same-origin` is accepted as the primary browser-controlled same-origin signal;
- other or missing Fetch Metadata falls back to explicit Origin hostname validation;
- fallback trusted hosts include `Host`, `X-Forwarded-Host`, `BOB_CONTROL_CENTER_PUBLIC_URL`, `VERCEL_PROJECT_PRODUCTION_URL`, `VERCEL_BRANCH_URL`, and `VERCEL_URL`.

The signed owner session and SameSite Strict session cookie remain required before the origin guard is evaluated.

## Security posture

This change does not disable CSRF protection.

`Sec-Fetch-Site` is a Fetch Metadata request header set by the browser. Ordinary cross-origin JavaScript cannot choose a forged `same-origin` value. Explicit `cross-site` requests remain blocked. Clients without Fetch Metadata still go through host/origin validation, while the signed owner session and SameSite Strict cookie remain independent defenses.

Bob Core continues to enforce the scoped Control Center credential, `decision:review`, project binding, and owner decision authority after the Web request passes.

## Validation

Before merge:

- Web TypeScript typecheck must pass;
- Next.js production build must pass;
- Vercel Control Center preview must be green;
- Bob Core preview must remain green because the monorepo deployment is triggered from the same commit.

Final functional acceptance remains an authenticated owner click on the existing pending Codex decision proposal from the production iPhone Control Center.

## Rollback

Revert this Web-only guard change. It does not modify Bob Core schema, stored proposals, decisions, credentials, or raw secrets.

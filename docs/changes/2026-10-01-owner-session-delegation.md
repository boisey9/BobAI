## Implemented contract

Server Web obtains an opaque one-use proof from a pinned private owner verifier, presenting its separate service credential and original cookie. The issuer calls injected authoritative getSession with cookie-cache disabled; it validates exact configured owner user/email, verified email, linked session/user, expiry and session version. No identity headers, agent grants or Core shared-owner token can issue owner authority. Web requires owner auth enabled, with an explicit loopback-only synthetic fixture exception; hosted/default-off gates remain.

The proof is random256bits; only its SHA256 hash is stored. Immutable claims bind protocolversion1, configured issuer/audience, owner/actor/user, session ID/version, expiry bounded by session expiry, exact method/path/query/body digest/project, and current authorized project-grant versions. Lifetime must be configured, no live default. Atomic UPDATE consumes once. Bad binding, expiry or replay fails closed, including concurrent redemption. Raw proof is server-only and never intentionally persisted in browser content/storage. Cookie travels only to the configured owner verifier, not Core.

Core uses a distinct private-verifier credential. It pins verifier issuer and own audience, validates response principals, and captures a redeemed per-request context. Each pinned transaction revalidates that same context before DB connection and before COMMIT; no global synthetic owner guard in user routes. Existing project RLS/locks and edit/review permission checks remain. Release is still denied. Separate service credentials do not confer owner power without a verified session proof and existing project grants; Web/Core service roles cannot substitute for one another. Current grant versions advance on updates so revoke/regrant cannot revive old proofs. Normal agent OAuth /mcp/linked audience, scopes and grants are unchanged.

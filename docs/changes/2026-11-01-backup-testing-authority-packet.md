## Execution gaps found by independent review

1. **No producer-to-recovery anchor handoff.** The [downloader](../../Core/scripts/lib/backup-download.mjs) requires exact trusted `id`, `instance`, `startedAt`, `recipientFingerprint`, `receiptSha256`, `receiptBytes`, `manifestBytes`. The job's terminal record exposes only run ID, archive byte count and retention result; the ledger stores object keys/archive hash/size but not the complete anchor set; the CLI deletes its local encrypted bundle on exit. The integration fixture keeps those values directly in memory. That is not an operational independent-custody path. Fetching a receipt from the same store and trusting its own hash would defeat this boundary.
2. **No download operator entry point.** The download library and bounded storage adapter exist, but no reviewed CLI binds an independently retained anchor file, Get-only authority, exact storage target, private destination, cancellation and cleanup. A documentation command must not pretend that entry point exists.
3. **Restore transport is specific.** `restore-database.mjs` uses Neon's WebSocket `Pool`; it is not a generic offline Docker/Unix-socket restore command. The real local fixture uses a psql bridge. Choose and qualify a distinct approved Neon destination for hosted testing, or implement a separately reviewed local adapter. The restore CLI does not consume/enforce `review.restoreTarget`; verify the actual URL/role/destination independently before invocation. This is separate from off-device Production recovery.
4. **Standalone preflight is preliminary.** `check-backup-coverage.mjs` uses the non-strict path. Its success does not prove the exporter's strict capture profile or the separate ledger profile; ledger validation is currently internal to job execution. Effective-grant denial checks and the integrated strict checks are required.

**Exact next implementation task: add a versioned, nonsecret capture-to-recovery handoff, default-off with the existing exporter.** Derive the downloader's seven fields from the exact locally verified receipt bytes and encrypted manifest length; preserve the same run ID/time/instance/recipient binding through the bounded supervisor protocol. Produce no credentials, raw rows, plaintext manifests, URLs or private keys. Retain the anchor through an authenticated channel independent of the object store, with explicit source/run/image identity and owner-approved custody. The first code slice must define failure and ambiguous-outcome semantics before claiming a durable handoff; a log line alone is not durable independent retention. No new memory authority, database migration or fourth backup object is needed.

Acceptance for that slice: exact anchor-to-uploaded-byte binding; rejection of wrong run/instance/recipient/hash/length, duplicate or conflicting protocol records, oversized/malformed output and secret sentinels; no successful handoff after failed capture/readback/ledger close; explicit treatment of lost acknowledgement; original run identity retained on failure; and an end-to-end synthetic download that consumes only the emitted/retained anchor after original bundle files are removed. Then implement the default-off Get-only download operator around the accepted contract and qualify the selected restore path.

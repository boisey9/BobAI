# Private protected HTTPS and governed-only startup — local successor

Scope: authorized local implementation only, based on independently accepted commit `6cb11bbe0599755a30d3b008222ca94a34c0fe4a`. Existing Core/Web project workflow only; no native/calendar/events/draft work or live access changes. Original repo and accepted worktree preserved.

## Behavior

- `Core/src/workflow/protected-transport.ts` pins exact trusted profile origins and necessary workflow/verifier methods/paths. It acquires a token per outbound call from the official locked `@vercel/oidc@3.8.10` helper, requiring trusted server request context. It does not refresh/exchange/issue identities, inspect CLI credentials, accept an incoming identity header as authority or fall back to an ambient build token. Header injection/transport replacement are trusted server-code test seams. Unneeded cookies and caller bypass/identity headers are removed; owner cookie is forwarded only to the private issue path. Redirects, non-HTTPS/non-allowlisted destinations and unavailable identity fail closed.
- Explicit `BOB_WORKFLOW_PROTECTED_TRANSPORT_ENABLED=true` plus strict `BOB_WORKFLOW_PLATFORM_BINDING` metadata (issuer/audience/team/project/preview) is required. JSON payload checks reject bad/mismatched/expired/not-yet-valid tokens but do NOT authenticate signatures. Independently configured receiving platform protection must do that. Personal owner proofs remain single-use/exact-action-bound; platform identity is a reusable workload transport credential, not owner/release authority.
- `BOB_WORKFLOW_PRIVATE_RUNTIME_ENABLED=true` selects a preview-only private deployed entry through `Core/src/index.ts`/`Core/index.ts`. It exposes only health and governed routes and does not initialize legacy AI/device/agent services. Invalid private config throws without legacy fallback. Normal Core remains unchanged when off; the existing legacy development CLI remains legacy. No need to provision dummy AI keys.
- Core verifier calls and hosted Web workflow calls use the protected transport. Web navigation/proxy stays closed unless the complete hosted/protected metadata is present. Local browser fixture behavior remains compatible. Hosted verifier application authorization/current-session/project checks, pinned DB transactions, immutable evidence and legacy task semantics remain intact.

## Bootstrap boundary

`local-private-bootstrap.mjs` is a local rehearsal helper, not a hosted provisioning command. It requires its own marker/data-directory/socket/bin/port, verifies local DB identity, checks an empty explicitly named disposable DB and exact reviewed migration hashes. One transaction applies prerequisite/governed/proof/private-record schema and three NOLOGIN, NOSUPERUSER, NOBYPASSRLS, NOCREATEDB, NOCREATEROLE roles. It creates no owner grants, policy/issuer acceptance, credentials or release access. Forced failure rolls back schema/roles; retry rejects a populated target. The synthetic dump/restore retains data/RLS/ACLs. No destructive down rollback or scheduled backup is enabled. Live parameterized operator/custody/backup approval and real target schema acceptance remain separate.

## Limits / remaining production gates

The new edge is local synthetic JWT verification over actual HTTPS; it is not Vercel's deployed Trusted Sources configuration. No Vercel identity issuance, trust grant, protection/hosting/env/credential/provider change, push/PR/deploy or live migration occurred. Actual configured preview origins/project IDs/claims and effective inherited env isolation must be verified before activation. Existing two apps and empty isolated DB capacity are proposals until that check succeeds. Scoped live credentials/roles/bootstrap, protection rules, artifact/config/schema binding, HTTPS reachability, owner enrollment, capacity/cost and rollback/restore require explicit approval. Mandatory baseline/check/independent evidence issuer and release activation remain fail-closed. Distributed revocation after final check but before cross-service commit is still a residual race, not atomic revocation.
